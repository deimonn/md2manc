# Name

md2manc - convert markdown to roff man page

# Synopsis

```Usage
md2manc [-h|--help] [--version] [-t title] [-s section] [-d date] [-S source]
        [-V volume] [--no-comment] [input-file]
```

# Description

**md2manc** is a tool for converting markdown to man pages. It reads from an _input-file_ (or from standard input if _input-file_ is omitted), and writes the resulting **man**(7) instructions to standard output.

If an _input-file_ is provided and its filename follows a _title_**.**_section_**.md** pattern, **md2manc** will infer the man page _title_ and _section_ from it. If it doesn't match the pattern, the filename without the **.md** suffix becomes the _title_, and the _section_ defaults to 1.

With no _input-file_, the _title_ defaults to UNTITLED. Use **-t** to set it explicitly instead.

# Options

+ **-h**, **--help**

  If passed, the tool just prints usage text and exits.

+ **--version**

  If passed, the tool just prints the program version and exits.

+ **-t** _title_

  Explicitly sets the man page title instead of trying to infer it.

+ **-s** _section_

  Explicitly sets the man page section number instead of trying to infer it.

+ **-d** _date_

  Sets the man page's center footer, which is conventionally expected to be the date of the last non-trivial change to the man page; e.g. "2026-09-27".

  Many projects just set this to the current date (when the page is generated) instead.

+ **-S** _source_

  Sets the man page's left footer, which is conventionally expected to be project name and version (i.e. its 'source'); e.g. "md2manc 0.1.0".

+ **-V** _volume_

  Explicitly sets the man page's section name instead of using the **man**(1) program's default.

+ **--no-comment**

  Disable the 'automatically generated by md2manc' comment at the top of the generated man page.

# Markup

**md2manc** supports the entire [CommonMark](https://spec.commonmark.org/) spec, but its output is subject to man page limitations:

- Only level 1 and level 2 headings are supported. Other headings will be rendered as **bold** text and generate a warning.

- Thematic breaks (`---`, `***`, `___`) and images are not supported and will generate a warning.

- Block quotes just introduce indentation.

- ***Bold-italics*** will just be rendered as **bold**.

- Inline code literals are rendered as regular text, but can still be used to avoid interpreting markdown text specially.

- HTML tags are not recognized; HTML will be parsed just like any other piece of Markdown.

## Definition lists

**md2manc** supports definition lists as an extension via the following syntax:

```
+ Term

  Definition
```

This renders as:

+ Term

  Definition

## Code blocks

Code blocks in the **Synopsis** are treated specially.

Firstly, they will not be indented, as **Synopsis** contents conventionally aren't.

Secondly, fenced code blocks will be highlighted when given one of the following language tags:

+ **C**

  Highlights the code for C function documentation (section 3 man pages).

  Note that **md2manc** here knowingly disobeys the conventions set by **man-pages**(7).

  Going by the **man-pages**(7) definition, for C function documentation everything should be **bold** except for parameters, which should be _italics_.

  **md2manc** instead sets both parameters and fields in *italics*, while setting struct and union tags, variable names and function names in **bold**. Everything else gets the regular font.

  This is done to provide some cleaner visual distinction between the various elements of C code, where the old convention doesn't feel as helpful.

+ **Usage**

  Highlights the code for command documentation (section 1 man pages). Tries to match **man-pages**(7) conventions by making the following assumptions:

  - Words at the beginning of a line, without any preceding whitespace, are command names and set in **bold**.
  - Words beginning with `-` are option names and also set in **bold**.
  - Other words consisting of alphanumeric characters and dashes are arguments and set in _italics_.

## Relative links

Relative links are purposefully stripped, as they don't make much sense to have in a man page.

This can be used advantageously; e.g. to have a relative link to a man page in a rendered HTML page, but have the actual man page contain a simple **name**(n) reference.

# Exit status

+ **0**

  Document was successfully converted.

+ **1**

  An error occurred during conversion.

+ **2**

  Bad command line.
